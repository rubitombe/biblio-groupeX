# Circulation de l'information : groupe [nom du groupe]

À compléter par le groupe en séance 1. Chaque section est rédigée et poussée par un membre différent.

## 1. Rôles
Rédigé par : avrilbrngnzz-boop

Les issues sont crées par les membre de l'équipe lorsqu'un bug, une évolution ou une question est identifié par un des membre du projet 

Les pull requests sont relues par un autre membre du projet avant de merge 

Le merge est décidé après la relecture et la validation du pull request
## 2. Où circule chaque information
Rédigé par : @Asma-Mouhli

| Information | Qui la produit | Qui la valide | Où elle est stockée | Durée de vie |
|---|---|---|---|---|
| Code source | Le membre qui développe la modification | Un autre membre lors de la relecture de la pull request | Dépôt GitHub biblio-groupeX | Toute la durée du projet, historique conservé |
| Bug signalé | Le membre qui reproduit le bug | Un camarade qui teste les étapes indiquées | Issue GitHub | Jusqu’à résolution, puis conservé dans les issues fermées |
| Décision technique | Un membre ou le groupe | Les membres concernés | Issue ou pull request concernée | Jusqu’à remplacement, historique conservé |
| Documentation d'installation | Le membre qui rédige les instructions | Un camarade qui teste l’installation | README.md du dépôt | Toute la durée du projet, mise à jour si nécessaire |
| Question rapide entre membres | Un membre du groupe | Le membre qui vérifie et répond | Chat du groupe ; réponse utile reportée dans une issue ou la documentation | Courte dans le chat, durable si reportée |
| Compte rendu de réunion | Le membre désigné pour prendre les notes | Les participants à la réunion | Fichier Markdown dans docs/reunions/ | Toute la durée du projet |
## 3. Règles de l'équipe
Rédigé par : @pseudo

Format des titres d'issue, labels utilisés, qui trie, qui assigne.
Règle à partir de la séance 2 : aucun push direct sur main, tout passe par une pull request relue.
